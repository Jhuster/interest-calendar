# 存储与部署规格

状态：已实现。本文是实现和复查的契约。与 `docs/方案设计.md` 里仍保留的局域网叙述冲突时，以本文为准。不记录、也不依赖任何实测行数或字节数；仓库里没有运行库，也没有七天试运行的体积数据。

## 1. 为什么要改

服务将放到 ECS 或其它云虚拟机上长期无人值守运行。当前 `main`（PR #1 已合并）有三件会把磁盘写满的事，写满后 SQLite 写入变成 503，备份失败只记 `backup_error`，日历停止更新。若数据目录在系统盘上，整台虚拟机会受影响。

同时，原设计假定可信局域网：进程监听 `0.0.0.0:8787`，固定路径 `/calendar.ics` 无需登录。云防火墙或安全组一旦把该端口对公网放开，日程和来源链接对整个互联网可读，管理令牌和 Agent 令牌在默认 HTTP 上明文传输。监听所有网卡不是防火墙。

## 2. 已核对的当前行为

以下行为以实现为准，不是目标。

| 对象 | 当前行为 |
| --- | --- |
| `publications` | `publish()` 每次成功发布 `INSERT` 一整份 ICS。只读 `settings.active_publication_id`。除管理员重置外不删除。重置没有 `VACUUM`，文件不把空页还给系统 |
| `event_versions` | 每次非空修改追加完整事件 JSON。不删除 |
| `batches` | 每个新 `batch_id` 保留哈希和回执（不是上传正文）。相同 ID 重传不新增。设计禁止回收已用 ID |
| `events` / `event_sources` / `candidates` / 软删除的 `interests` | 按身份一行，修改原地更新。撤下不删事件行。无按时间清理 |
| `audit_log` | 只在候选处理和管理员重置时写入 |
| `backups/*.sqlite3` | 每个 UTC 日自动最多新写一份整库；手工备份再写一份后按文件名只留 7 个 `*.sqlite3`。当天文件已存在则不再重写。份数有顶，字节没有，因为库本身没有顶 |
| `restore-preserved/` | 每次 `restore --apply` 拷一整库，不删除旧文件 |
| `restore-reports/` | 每次恢复（含不 `--apply`）写一份文本，不删除 |
| `server.log` | `rotate_log` 在 `start-background.sh` 启动前执行：超过 1 MiB 则改名轮转，保留 7 份，权限 0600。进程运行期间不轮转。`>>` 已打开的文件描述符在改名后仍写入旧 inode。Docker 入口不调用轮转，日志在容器标准输出 |
| 订阅 | 改前是匿名 `GET/HEAD /calendar.ics`，非开发模式地址为 `BASE_URL/calendar.ics`，开发模式不在页面展示地址。现行为见第 5 节 |
| 凭据 | `credentials.json` 存管理员和 Agent 的哈希及原文，权限 0600。首次启动另写 `first-run-credentials.txt`，代码不删除。后台非交互标准输出不打印令牌原文。数据库备份不含凭据 |
| 其他 | 无独立 `.ics` 文件。未开 WAL。无 `max_page_count`。会话只在内存 |

## 3. 必须保留、禁止覆盖

这些数据没有容量上限，也不允许用「写满就覆盖」腾出空间。

- `events`、`event_sources`、`event_interests`：当前日历。撤下和取消仍留在事件行里。
- 仍被事件引用的 `interests` 行，包括 `deleted_at` 非空的归档兴趣。
- `candidates` 的现有行。同一 `client_candidate_id` 的幂等依赖它，不能删掉已处理行再让下次上传新建。
- `batches` 的 `batch_id`、`payload_hash`、状态。回执可以以后变短，但本规格不压缩回执，也不得复用或删除已用 `batch_id`。
- `credentials.json` 里的管理员令牌、Agent 令牌，以及下面新增的订阅密钥。重启不得轮换。数据库恢复不得改写该文件，也不得让已轮换的旧令牌复活。
- `event_versions` 与 `audit_log`：本规格不清理。

磁盘满时的行为保持现状：备份失败可见，随后写入返回 503。不要为了腾空间删除上表。

## 4. 要轮转或截断的对象

数量都是硬上限。选择与现有「7 份」对齐的，在下面写明；没有现成数字的，取更小的那个。

### 4.1 日历快照：当前加上一份

一次成功发布在同一写事务内：

1. 记住发布前的 `active_publication_id`（没有则为空）。
2. 插入新的 `publications` 行，并把指针改到新行。
3. 删除其余行。留下的只能是新行，以及第 1 步那个旧指针（若仍存在）。按指针留，不按 `created_at` 挑「最新两行」。
4. 事务提交后，若删除行数大于 0，再执行 `VACUUM`。`VACUUM` 不能包在该写事务里。`VACUUM` 失败不得回滚已经提交的新快照，也不得把发布失败重试标成失败；记录一次错误即可。

因此每个账户的 `publications` 最多留下当前和上一份。全库行数随账户数增加，不是全局只留 2 行。一次发布只删除该账户指针之外的快照，不删除其他账户的行。第一次发布只有当前行。展示版本重建会再插入一行，并留下重建前那一行。

管理员重置会删掉**当前账户**的全部快照再插入一份空日历，不碰其他账户。重置事务提交后同样 `VACUUM`，使事件和快照占用的页能还给系统。重置失败或确认条件不满足时不得 `VACUUM`。

已经写在 `backups/` 里的文件不要当场改写。当天自动备份若已存在，继续跳过。活库变小之后，下一次真正写入的备份（下个 UTC 日，或手工 `backup`）才会变成较小的整库；旧的 7 份仍按现有文件名规则被顶掉。不承诺备份目录在 `VACUUM` 的同一秒变小。

### 4.2 恢复前数据库：只留最新 1 份

`restore --apply` 成功把当前库复制到 `restore-preserved/` 之后，删除该目录中其余 `*.sqlite3`。复制失败时不要删已有文件。不 `--apply` 的预览不写这个目录。上限是 1，不是 7。

### 4.3 恢复报告：最多 7 份

每次写出 `restore-reports/*.txt` 之后，按文件名排序只留最后 7 个。文件名继续用 UTC 时间戳，时钟正常时即最新 7 份。预览和 `--apply` 都计数。

### 4.4 运行中的日志

两套动作，阈值相同：超过 1 MiB 才动，保留 7 份归档，文件权限 0600。

- 启动前：`start-background.sh` 继续在打开日志之前用改名轮转。此时进程尚未持有文件。
- 运行中：服务循环（与现有发布、备份检查同一循环）若发现日志已存在且大于 1 MiB，把当前内容复制到 `.1`，再把原文件截断为 0。必须截断同一 inode。不能在进程已用 `>>` 打开文件后再改名，否则后续输出仍写入旧文件。归档 `.1`–`.7` 的递推和丢弃规则与启动前轮转相同。文件不存在时不要创建。前台 `start.sh` 的终端输出不落 `server.log`，因此没有文件就不轮转。
- 环境变量 `CALENDAR_LOG_FILE` 由后台脚本导出。未设置时只检查数据目录下的 `server.log`。
- 轮转失败不得拖垮发布循环。

Docker 镜像不写 `server.log`，标准输出由守护进程采集。镜像里无法声明 `json-file` 上限。文档中的 `docker run` 必须带 `--log-opt max-size=1m --log-opt max-file=7`。`Dockerfile` 用注释指向该命令，避免以为镜像已经限了大小。

## 5. 订阅地址与公网边界

固定路径 `/calendar.ics` 改为 404，登录用户也一样。不要把它留在匿名名单里。

新的只读地址是 `BASE_URL/c/{token}/calendar.ics`，支持 `GET` 和 `HEAD`，仍用现有 ETag 与 `Cache-Control: no-cache`。密钥放在路径里，不放查询串：手机「订阅日历」不发送 `Authorization`，查询串也容易被客户端丢掉。

- 密钥用 `secrets.token_urlsafe(32)`，只生成一次，存在 `credentials.json` 的 `calendar`（SHA-256）和 `calendar_token`（原文）。权限保持 0600。这是**公开账户**的订阅密钥。进程打开数据库时把它写回公开账户。受邀账户另有订阅密钥，存在数据库账户行里，不进 `credentials.json`，也不进 `first-run-credentials.txt`。登录令牌和订阅密钥不是同一个值。规则见 `docs/账户规格.md`。`rotate --role calendar` 只更换公开账户的地址。
- 比较时用 `hmac.compare_digest` 对哈希。密钥错误、缺失、已撤销或路径不对，一律 404，不要 401。公开账户不会被撤销。
- 不把该密钥写入 `first-run-credentials.txt`、`server.log` 或非交互标准输出。访问日志保持关闭，避免路径里的密钥进日志。
- 重启不轮换。`rotate --role calendar` 可以轮换；轮换后手机必须改用新地址。设置页仍说明：不轮换订阅密钥时，增添兴趣不用重新订阅。
- `subscription_url` 使用上述密钥路径。主机名不是回环的 `BASE_URL` 原样作为来源，不另做探测，也不为它多开监听。
- `--dev` 与普通启动一样，只在 `BASE_URL` 的端口上听 `0.0.0.0`。不再为 `--dev` 单独绑 `127.0.0.1`，否则手机访问不到设置页给出的局域网地址。不额外增加第二块网卡上的监听。
- `--dev` 且 `BASE_URL` 主机是回环时，用已有的 `detect_local_ip()` 取本机局域网 IPv4。该函数只做一次不监听端口的探测，失败时返回 `127.0.0.1`。探测到非回环地址才展示 `http://<局域网IP>:<端口>/c/<token>/calendar.ics`；端口取自 `BASE_URL`，缺省 8787。Host 允许名单同时包含 `BASE_URL` 的主机名和这个局域网主机名，写请求的 Origin 也接受这两个来源。其它 Host 仍拒绝。探测不到时 `subscription_url` 为空，设置页保留原文：「当前是本机开发预览，127.0.0.1 只能由这台电脑访问，不能复制到手机。请用固定局域网 IP 配置 BASE_URL 后再订阅。」不要编造地址。
- 校验仍要求 `--dev` 的 `BASE_URL` 本身是回环。有订阅地址时，设置页改为密钥说明，不再显示上面的回环说明。密钥路径不变。
- 设置页说明：知道完整地址的人可以读取日程标题、地点、时间和来源链接；兴趣条件和证据摘录仍不在 ICS 里。

公网部署约束（文档和设置页，不把 HTTP 启动变成程序错误，以免破坏现有局域网用法）：

- `0.0.0.0` 只表示进程接受该机器上的连接。能否从互联网连上，取决于云防火墙或安全组。应用内不做来源 IP 白名单。
- 对公网放行端口之前，`BASE_URL` 必须是 `https`，并用已有的 `--cert`/`--key`，或在反向代理上终止 TLS。默认 HTTP 会把管理令牌、会话 Cookie 和 Agent 令牌暴露在路径上。本规格不自动签发证书。
- 首次启动后，操作者保存令牌并删除 `first-run-credentials.txt`。代码仍不自动删这个文件，因为操作者可能还没保存。
- 本机 `bin/start.sh` 与 `bin/start-background.sh` 不传 `--dev`，未设置 `BASE_URL` 时仍探测局域网地址。它们不是云主机的启动方式。
- 公网机器用 `bin/start-ecs.sh`。它不探测地址、不传 `--dev`、不改监听：仍是程序默认的 `0.0.0.0`，端口来自 `BASE_URL`，缺省 8787。`BASE_URL` 必须是 https 源。同时设置 `CALENDAR_CERT` 与 `CALENDAR_KEY` 时传给已有的 `--cert`/`--key`；否则由反向代理终止 TLS，并且不要把 8787 对 `0.0.0.0/0` 做 HTTP 发布。这条脚本会拒绝非 https。应用进程本身仍允许 HTTP 启动。容器入口同样不传 `--dev`；只有两个证书变量都存在时才追加 `--cert`/`--key`。订阅地址仍是设置页中的 `/c/{token}/calendar.ics`。

## 6. 明确不做

- 不清理 `event_versions`、`audit_log`、历史事件、候选、归档兴趣，不压缩批次回执，不回收 `batch_id`。
- 不引入 WAL、`max_page_count`，也不在每次请求时 `VACUUM`。只在第 4.1 节的删除提交之后 `VACUUM`。
- 不重写已经生成的当日备份。
- 不把监听地址改成仅回环，不加应用层防火墙，不拒绝 HTTP 启动。
- 不做真实 Agent、iPhone 试订阅、launchd 或证书自动续期。
- 不编造库将占用多少字节。

## 7. 复查标准

- 连续三次会改变同一账户日历的发布之后，该账户的 `publications` 只有当前和上一份；更早的 blob 不在。其它账户的快照不受这次删除影响。`events` 与 `batches` 行数不因这次删除而减少。
- 删除过大的旧快照并 `VACUUM` 之后，`PRAGMA freelist_count` 为 0，且 `page_count` 小于删除前。`VACUUM` 失败时新指针仍可用。
- 管理员重置提交后执行 `VACUUM`。未通过确认的重置不执行。
- 两次 `restore --apply` 之后，`restore-preserved` 里只有 1 个 `*.sqlite3`。八次恢复报告之后只有 7 个 `*.txt`。
- 用追加方式打开日志并在超过阈值后轮转，随后写入的字节出现在原路径，旧内容在 `.1`。保留份数到达上限后最旧归档被删除。文件不存在时轮转不会创建它。
- 无密钥的 `/calendar.ics` 和错误密钥都是 404。正确密钥返回当前快照，`If-None-Match` 仍为 304。订阅地址包含 `/c/{token}/calendar.ics`。密钥不出现在非交互启动输出和首次凭据文件中。
- `--dev` 且 `BASE_URL` 为回环时：探测到局域网地址则状态里的订阅地址是 `http://<该地址>:<端口>/c/<token>/calendar.ics`，且该主机名的 `GET` 能取到日历；探测结果仍是回环则地址为空。显式非回环 `BASE_URL` 不被探测结果替换。`--dev` 的监听主机是 `0.0.0.0`，端口仍是 `BASE_URL` 的端口。无密钥路径仍是 404。
- `docker run` 示例包含 `max-size=1m` 和 `max-file=7`。
