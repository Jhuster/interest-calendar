# 账户规格

状态：已实现。本文是邀请制账户的实现和复查契约。与 `docs/存储与部署规格.md` 冲突时，快照片数按账户计，订阅密钥按账户计；其余存储上限仍以该文为准。不改 Agent 令牌、上传协议和 Agent 的运行方式。

## 1. 为什么要改

现在全站只有一个管理员会话。打开首页就会被送到登录页，兴趣、事件和批次都写在同一组表里。要让别人各自看自己的日历，又不能让他们自己注册，也不能把管理员令牌交出去。

## 2. 已核对的当前行为

| 对象 | 当前行为 |
| --- | --- |
| 登录 | `POST /api/v1/session` 只接受 `credentials.json` 里的管理员令牌。成功后写 `session` Cookie。没有密码，也没有注册接口 |
| 页面 | 除 `/login` 外，页面都要求管理员会话。没有会话时 `/` 返回 303 到 `/login` |
| 订阅 | 全站一份日历密钥，在 `credentials.json` 的 `calendar` / `calendar_token`。地址是 `/c/{token}/calendar.ics`。固定路径 `/calendar.ics` 为 404 |
| 数据 | `interests`、`events`、`batches` 等表没有账户列。`settings` 只有 `id=1` 的一行 |
| Agent | 一个 Agent 令牌。`GET /api/v1/agent/context` 与 `POST /api/v1/batches` 的请求和响应形状不变。上传写入上面那一组不分区的表 |

## 3. 账户

两类账户，都存在数据库里，不另做注册表。

- **公开账户**正好一个，随数据库创建。没有登录令牌。匿名访客看的就是它的日程。
- **受邀账户**由管理员在登录后创建。每个受邀账户有自己的登录令牌和另一份订阅密钥。

没有自助注册，没有密码。登录接口仍然只收一个 `token` 字符串。

### 3.1 令牌

- 管理员令牌仍只有一个，仍在 `credentials.json`。轮换方式不变。
- 邀请令牌用 `secrets.token_urlsafe(32)`。数据库只存 SHA-256。创建和重新签发时在响应里给出原文，各一次。不写入 `credentials.json`、`first-run-credentials.txt` 或日志。
- 订阅密钥与登录令牌不是同一个随机数，也不由登录令牌推导。订阅密钥可重复读取，因为设置页要显示完整地址；比较时仍对哈希用 `hmac.compare_digest`。
- 重新签发邀请令牌只更换登录哈希。订阅密钥和 `/c/{订阅密钥}/calendar.ics` 不变。
- 公开账户的订阅密钥仍与 `credentials.json` 里的 `calendar_token` 保持一致。`rotate --role calendar` 只影响公开账户，不影响受邀账户。进程下次打开数据库时把该文件中的密钥写回公开账户。

### 3.2 撤销

管理员可以撤销一个受邀账户，不能撤销公开账户。

- 已撤销的邀请令牌不能登录。已有的该账户会话在下一次请求失效。
- 该账户已发出的日历地址改为 **404**。不继续提供最后一份快照，也不做“停止更新但仍可订阅”的第二种状态。快照行可以留在库里，接口不读它。
- 这是较小的行为：feed 多一次撤销判断，不必另做冻结发布。

### 3.3 会话

- 打开网站不是登录。匿名请求不写 `session` Cookie，也不自动进入任何账户。
- 管理员登录后，会话先落在公开账户。管理员可以改公开账户的兴趣，也可以切入某个受邀账户；切入后兴趣、日程、候选和重置都作用在该账户上。
- 受邀者用自己的邀请令牌登录后，只进入自己的账户。不能切入别人，也不能拿 Agent 令牌。
- 退出或会话失效之后，再打开网站仍是公开日历，不是刚才那个受邀账户。

匿名可以读公开账户已发布到页面上的日程和兴趣名称。不能改兴趣，不能看订阅密钥，不能看 Agent 令牌。公开账户的兴趣只有管理员会话能改。受邀者只能改自己账户的兴趣。

## 4. 数据按账户分开

`interests`、`events`、`event_sources`、`candidates`、`batches`、`publications` 以及每个账户自己的 `settings`（`state_epoch`、`config_version`、`data_revision`、`active_publication_id`）都带账户。查询和写入都带账户条件，行不共用。

- 兴趣的“未删除则唯一”按账户加关键词，不按全库。
- 来源键、候选键在账户内唯一。`batch_id` 仍全库唯一，不回收；行上仍记它属于哪个账户。
- 快照仍只留该账户的当前指针和上一指针。一个账户的发布不删除另一个账户的快照。
- 重置只清当前会话所在账户。管理员才能重置。受邀者不能重置。

现有的单个 Agent 令牌和 `POST /api/v1/batches` 的 JSON 不变。Agent 上下文和上传只读写**公开账户**。不为受邀账户发放 Agent 令牌，也不做 Agent 运行器。受邀账户的日程只会来自该账户自己的行；在本规格里，这些行不会由现有 Agent 写入。

## 5. 明确不做

- 不改 Agent 接入说明的字段、上传路径、重试语义和 Agent 令牌的存放。
- 不做自助注册、密码、邮箱验证码。
- 不把撤销做成“日历仍可订阅但不再更新”。
- 不为每个账户做一套 Agent。

## 6. 复查标准

- 无 Cookie 打开 `/` 为 200，响应不设置 `session`。匿名 `GET /api/v1/events` 只含公开账户的可见日程。匿名不能新增兴趣。
- 管理员可以新增公开账户的兴趣。受邀者登录后看不到这条兴趣；匿名再访问也看不到受邀者自己添加的兴趣。
- 创建邀请的响应里，登录令牌与订阅地址中的密钥不同。重新签发登录令牌后，订阅地址不变，旧登录令牌失效。
- 撤销后，该登录令牌不能建立会话，原日历地址为 404。公开账户日历地址仍可用。
- 管理员切入受邀账户后可以改该账户的兴趣；退出后首页回到公开日历。

## 7. 实现位置

| 规则 | 位置 |
| --- | --- |
| 账户、邀请哈希、按账户的 settings；从旧库迁入公开账户 | `src/app/storage/database.py` |
| 兴趣、事件、批次按账户读写；Agent 路径仍只碰公开账户 | `src/app/services/domain.py` |
| 每个账户单独发布，并只修剪该账户的快照 | `src/app/services/calendar.py` |
| 匿名读、邀请登录、撤销、切入账户 | `src/app/main.py`；设置页在 `src/app/templates/index.html` 与 `src/app/static/app.js` |

对应测试在 `src/tests/test_application.py`：`test_anonymous_public_calendar`、`test_invite_login_is_isolated`、`test_login_token_is_not_calendar_secret`、`test_revoked_invite_cannot_login_and_calendar_is_404`、`test_admin_edits_public_interests`。
