# 账户规格

状态：已实现。本文是邀请制账户的实现和复查契约。与 `docs/存储与部署规格.md` 冲突时，快照片数按账户计，订阅地址按本文的公开路径与个人路径分开；其余存储上限仍以该文为准。不改 Agent 令牌、上传协议和 Agent 的运行方式。

## 1. 为什么要改

现在全站只有一个管理员会话。打开首页就会被送到登录页，兴趣、事件和批次都写在同一组表里。要让别人各自看自己的日历，又不能让他们自己注册，也不能把管理员令牌交出去。

公开日历要能被任何人订阅。受邀用户的兴趣和订阅地址是隐私，管理员不能代看。令牌管理、订阅和大模型配置分成独立页面。

## 2. 已核对的当前行为

| 对象 | 当前行为 |
| --- | --- |
| 登录 | `POST /api/v1/session` 只接受 `credentials.json` 里的管理员令牌。成功后写 `session` Cookie。没有密码，也没有注册接口 |
| 页面 | 除 `/login` 外，页面都要求管理员会话。没有会话时 `/` 返回 303 到 `/login` |
| 订阅 | 全站一份日历密钥，在 `credentials.json` 的 `calendar` / `calendar_token`。地址是 `/c/{token}/calendar.ics`。固定路径 `/calendar.ics` 为 404 |
| 数据 | `interests`、`events`、`batches` 等表没有账户列。`settings` 只有 `id=1` 的一行 |
| Agent | 一个 Agent 令牌。`GET /api/v1/agent/context` 与 `POST /api/v1/batches` 的请求和响应形状不变。上传写入上面那一组不分区的表 |

## 3. 账户

两类账户，都存在数据库里，不另做注册表。

- **公开账户**正好一个，随数据库创建。没有登录令牌。匿名访客看的就是它的日程，订阅的也是它的日历。
- **受邀账户**由管理员在登录后创建。每个受邀账户有自己的登录令牌和另一份订阅密钥。

没有自助注册，没有密码。登录接口仍然只收一个 `token` 字符串。

### 3.1 令牌

- 管理员令牌仍只有一个，仍在 `credentials.json`。轮换方式不变。
- 邀请令牌用 `secrets.token_urlsafe(32)`。数据库存 SHA-256，并另存原文，供管理员之后点开该账号再查看。创建和重新签发的响应里给出原文。账户列表不包含令牌。不写入 `credentials.json`、`first-run-credentials.txt` 或日志。这些响应不给订阅地址，也不给订阅密钥。
- 管理员账号没有邀请令牌。点开它时，查看接口返回 `credentials.json` 里的管理员令牌。原文已经不在时，接口说明需要在本机重新生成，不编造一个新值。
- 订阅密钥与登录令牌不是同一个随机数，也不由登录令牌推导。比较时对哈希用 `hmac.compare_digest`。
- 重新签发邀请令牌只更换登录哈希。该用户的订阅密钥和 `/c/{订阅密钥}/calendar.ics` 不变。这个地址只在该用户自己登录后的「订阅」页出现。
- 公开日历的地址是固定路径 `/public/calendar.ics`，不是密钥。`credentials.json` 里的 `calendar_token` 仍会在进程打开数据库时写回公开账户，但公开 feed 不读它。`rotate --role calendar` 不改变公开订阅地址，也不改变受邀账户的 `/c/{token}` 路径。
- 用公开账户那份 `calendar_token` 去请求 `/c/{token}/calendar.ics` 得到 404。个人路径只匹配 `kind='invite'` 且未撤销的账户。

### 3.2 撤销

管理员可以撤销一个受邀账户，不能撤销公开账户。

- 已撤销的邀请令牌不能登录。已有的该账户会话在下一次请求失效。
- 该账户已发出的日历地址改为 **404**。不继续提供最后一份快照，也不做“停止更新但仍可订阅”的第二种状态。快照行可以留在库里，接口不读它。
- 这是较小的行为：feed 多一次撤销判断，不必另做冻结发布。公开地址 `/public/calendar.ics` 不受撤销影响。

### 3.3 会话与隐私

- 打开网站不是登录。匿名请求不写 `session` Cookie，也不自动进入任何账户。
- 管理员登录后只落在公开账户。兴趣、日程、候选和订阅地址都是这一份。没有切入受邀账户的接口。`POST /api/v1/admin/session/account` 不存在。
- 管理员不能读取受邀用户的兴趣、事件或日历内容。列表和按 id 读取都按公开账户过滤；用受邀账户的事件 id 请求得到 404。账户列表只含 id、种类、备注、撤销时间、创建时间，以及执行重置所需的 `state_epoch` 和 `config_version`。不含登录令牌、兴趣、事件或订阅地址。点开某个账号的查看接口只返回该登录令牌，不返回兴趣。
- 受邀者用自己的邀请令牌登录后，只进入自己的账户。只能看和改自己的兴趣。不能切入别人，也不能拿 Agent 令牌，也不能打开管理后台或大模型页。
- 退出或会话失效之后，再打开网站仍是管理员那一份只读内容，不是刚才那个受邀账户。

日程、兴趣、订阅是同一套页面、同一套标题和文案。差别只在会话：管理员登录时配置和看到的是公开账户的日历和兴趣，订阅地址也是这一份；其他账户登录时配置和看到的是自己的日历和兴趣；未登录时只读展示管理员那一份，包括日程、兴趣和订阅，不能改。普通页面不写「公共日历」「公开日历的兴趣」这类把两套东西拆开的说法。

匿名可以读公开账户已发布到页面上的日程和兴趣名称，也可以在「订阅」页复制公开订阅地址。不能改兴趣，不能看个人订阅密钥，不能看 Agent 令牌。公开账户的兴趣只有管理员会话能改。受邀者只能改自己账户的兴趣。

### 3.4 页面

不再有「设置」页。`GET /settings` 为 404。

导航对所有人显示三项：**日程** `/`、**兴趣** `/interests`、**订阅** `/subscribe`。管理员会话再显示两项：**大模型** `/model`、**管理后台** `/admin`。未登录时，任意页的页头右上角只有一个「登录」。点击后在当前页弹出小窗填写登录令牌，提交成功就留在当前页并进入该令牌对应的账户，不跳到单独的登录页。正文里的「登录」不加链接。已登录时同一位置只有「退出」，不同时再放「登录」。

| 页面 | 谁能打开 | 内容 |
| --- | --- | --- |
| `/` | 任何人 | 日程。标题和说明不随登录变化，不放订阅地址。未登录只读。已登录处理的是当前会话那一份 |
| `/interests` | 任何人 | 标题是「兴趣」，说明不随登录变化，不写「公共日历」。未登录为 200，只读展示管理员那一份，没有添加表单和移除按钮。已登录可以改当前会话的兴趣。`POST` 与 `DELETE` 仍要登录，无会话为 401 |
| `/subscribe` | 任何人 | 标题固定为「日历地址」，周围说明和步骤不随登录变化。未登录或管理员看到 `/public/calendar.ics`；其他账户只看到自己的 `/c/{token}/calendar.ics`。个人地址保留订阅密钥说明。不写监听、防火墙、HTTPS 或安全组，也不写「公开日历」。不放手动发布按钮；发布失败由服务自己重试。步骤只写 iOS 和 Android，不写鸿蒙，也不留「暂不支持」 |
| `/model` | 仅管理员 | 先说明兴趣日程要由大模型 Agent 定期搜索并上传，再给出原来的接入流程：接入说明、服务器地址、Agent 令牌、接入指引、最近接收，以及运行记录入口。接入说明里不写「连续三天无法连接才询问」那段。无会话或其他账户直接打开为 **403**，不转到登录页 |
| `/admin` | 仅管理员 | 「管理账号」在同一页列出管理员账号和其他账户，不分成两套页面。列表默认只显示账号信息，不放登录令牌全文。点某个账号再查看它的令牌；创建或重新签发时也显示。可以创建账户，可以禁用其他账户。禁用沿用撤销：该令牌不能再登录，该账号的日历地址变为 404。不能禁用管理员自己。不显示兴趣内容，不显示订阅地址，不能切换账户。另有「删除和重置」：选择一个账户后，只清该账户自己的日历；管理员账号就是公开账户，可以选择。无会话或其他账户直接打开为 **403** |

邀请和 Agent 令牌的接口仍只有管理员能调用。受邀者为 403，无会话的接口请求仍为 401。

## 4. 数据按账户分开

`interests`、`events`、`event_sources`、`candidates`、`batches`、`publications` 以及每个账户自己的 `settings`（`state_epoch`、`config_version`、`data_revision`、`active_publication_id`）都带账户。查询和写入都带账户条件，行不共用。

- 兴趣的“未删除则唯一”按账户加关键词，不按全库。
- 来源键、候选键在账户内唯一。`batch_id` 仍全库唯一，不回收；行上仍记它属于哪个账户。
- 快照仍只留该账户的当前指针和上一指针。一个账户的发布不删除另一个账户的快照。
- 删除和重置按账户进行，只清被选中的那一个账户。`calendar` 删该账户的事件、候选、批次和快照，保留兴趣，并写入一份空日历。`all` 再删该账户的兴趣。凭证和其他账户不动。管理员在管理后台选择账户，包括公共日历对应的管理员账户。不带 `account_id` 时仍清公开账户，以便已有调用不变。受邀者不能调用重置。重置响应不返回兴趣或日程。

现有的单个 Agent 令牌和 `POST /api/v1/batches` 的 JSON 不变。Agent 上下文和上传只读写**公开账户**。不为受邀账户发放 Agent 令牌，也不做 Agent 运行器。受邀账户的日程只会来自该账户自己的行；在本规格里，这些行不会由现有 Agent 写入。

## 5. 订阅地址

两条路径，不要混用。

- **公开**：`GET` 和 `HEAD /public/calendar.ics`。只读公开账户的当前快照。不需要登录，不使用路径密钥。`ETag` 与 `Cache-Control: no-cache` 与个人 feed 相同。`/calendar.ics` 仍是 404，不要把这个旧路径恢复成可读日历。
- **个人**：`GET` 和 `HEAD /c/{token}/calendar.ics`。只匹配未撤销的受邀账户。密钥错误、缺失、已撤销，或拿公开账户的 `calendar_token` 来请求，一律 404，不要 401。

`subscription_url()` 是来源加上 `/public/calendar.ics`。来源的算法不变：非回环的 `BASE_URL` 原样使用；`--dev` 且 `BASE_URL` 是回环时，用 `detect_local_ip()`，探测不到则地址为空，页面保留「127.0.0.1 只能由这台电脑访问」那段说明。个人地址仍由 `subscription_url_for(token)` 拼成来源加上 `/c/{token}/calendar.ics`。

匿名和管理员的 `GET /api/v1/status` 返回公开地址。其他账户的 status 只返回自己的个人地址。订阅地址只出现在「订阅」页，不出现在日程页。该页标题是「日历地址」。

订阅步骤按系统分开写，因为核对后的路径不一样。页面只写这两条，先不支持鸿蒙，也不留占位说明：

- **iOS**（Apple 支持文档）：打开「日历」，进入日历列表，点「添加日历」→「添加订阅日历」，粘贴地址。iOS 26 接着点「查找」；iOS 18 及更早点「订阅」。
- **Android**（Google 日历帮助）：手机上的 Google 日历应用不能粘贴订阅地址。用电脑浏览器打开 Google 日历，在「其他日历」旁点「添加其他日历」→「通过网址添加」，粘贴地址后添加。手机在同步后看到它。

## 6. 明确不做

- 不改 Agent 接入说明的字段、上传路径、重试语义和 Agent 令牌的存放。
- 不做自助注册、密码、邮箱验证码。
- 不把撤销做成“日历仍可订阅但不再更新”。
- 不为每个账户做一套 Agent。
- 不让管理员切换到受邀账户，也不在管理接口里返回个人订阅地址。
- 订阅页不写鸿蒙步骤，也不写「暂不支持」。
- 不把页头的「登录」做成跳转到单独登录页，也不在页面正文里给「登录」加链接。

## 7. 复查标准

- 无 Cookie 打开 `/`、`/interests`、`/subscribe` 都为 200，响应不设置 `session`。这三页标题和说明相同，不随登录改成另一套文案，页面上不出现「公共日历」或「公开日历的兴趣」。页头右上角是「登录」按钮，没有「退出」，也没有指向 `/login` 的链接；点开是当前页的登录小窗。正文里的「登录」不是链接。日程页没有订阅地址。`/interests` 的标题是「兴趣」，无会话时没有添加表单。`/subscribe` 的标题是「日历地址」，步骤只有 iOS 和 Android，没有鸿蒙说明。匿名 `GET /api/v1/events` 与 `GET /api/v1/interests` 只含公开账户的内容。匿名不能新增或删除兴趣。匿名 status 含公开订阅地址；`GET /public/calendar.ics` 返回公开快照。
- 已登录时页头同一位置是「退出」，不再同时放「登录」。
- 管理员可以新增公开账户的兴趣。受邀者登录后看不到这条兴趣；匿名再访问也看不到受邀者自己添加的兴趣。管理员也看不到受邀者的兴趣、事件或个人日历地址。账户列表不含登录令牌。`GET /api/v1/admin/accounts/{id}/token` 才返回该令牌，响应里没有兴趣。禁用后，该登录令牌不能建立会话，原个人日历地址为 404。
- 创建和重新签发的响应里只有登录令牌，没有订阅地址。受邀者登录后，status 里的个人地址与登录令牌不同。重新签发后个人地址不变，旧登录令牌失效。
- 禁用（撤销）后，该登录令牌不能建立会话，原个人日历地址为 404。公开地址仍可用。管理员账号不能禁用。
- `/admin` 与 `/model` 对无会话和受邀者都是 403，不是 303。管理员可以打开。`/settings` 为 404。邀请接口对受邀者为 403。
- 退出后首页回到公开日历。
- 管理员重置某个受邀账户后，该账户的对应数据被清空，公开账户的兴趣和日程还在。管理员的兴趣列表仍然看不到受邀账户的兴趣。

## 8. 实现位置

| 规则 | 位置 |
| --- | --- |
| 账户、邀请哈希、按账户的 settings；从旧库迁入公开账户 | `src/app/storage/database.py` |
| 兴趣、事件、批次按账户读写；Agent 路径仍只碰公开账户 | `src/app/services/domain.py` |
| 每个账户单独发布，并只修剪该账户的快照 | `src/app/services/calendar.py` |
| 公开地址 `/public/calendar.ics`；个人地址仍是 `/c/{token}` | `src/app/config.py` 的 `subscription_url`、`subscription_url_for`；`src/app/main.py` 的两条 feed |
| 匿名读、邀请登录、禁用；账户列表不含令牌，点开才返回原文；管理员不能切换账户，也不能读到受邀数据；重置可指定账户 | `src/app/main.py`；登录令牌原文在 `accounts.login_token` |
| 日程、兴趣、订阅、大模型、管理后台 | `src/app/templates/index.html` 与 `src/app/static/app.js` |

对应测试在 `src/tests/test_application.py`：`test_anonymous_public_calendar`、`test_invite_login_is_isolated`、`test_login_token_is_not_calendar_secret`、`test_revoked_invite_cannot_login_and_calendar_is_404`、`test_admin_edits_public_interests`、`test_calendar_secret_path_and_hidden_from_first_run`、`test_dev_subscription_uses_lan_ip_without_replacing_explicit_base_url`。
