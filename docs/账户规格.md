# 账户规格

状态：已实现。本文是邀请制账户的实现和复查契约。与 `docs/存储与部署规格.md` 冲突时，快照片数按账户计，订阅地址按本文的公开路径与个人路径分开；其余存储上限仍以该文为准。不改上传协议和 Agent 的运行方式。公开账户的 Agent 令牌仍在 `credentials.json`。每个受邀账户另有自己的 Agent 令牌。

## 1. 为什么要改

现在全站只有一个管理员会话。打开首页就会被送到登录页，兴趣、事件和批次都写在同一组表里。要让别人各自看自己的日历，又不能让他们自己注册，也不能把管理员令牌交出去。

公开日历要能被任何人订阅。受邀用户的兴趣和订阅地址是隐私，管理员不能代看。令牌管理、订阅和大模型配置分成独立页面。

## 2. 已核对的当前行为

| 对象 | 当前行为 |
| --- | --- |
| 登录 | `POST /api/v1/session` 只接受 `credentials.json` 里的管理员令牌。成功后写 `session` Cookie。没有密码，也没有注册接口 |
| 页面 | 除 `/login` 外，页面都要求管理员会话。没有会话时 `/` 返回 303 到 `/login` |
| 订阅 | 全站一份日历密钥，在 `credentials.json` 的 `calendar` / `calendar_token`。地址是 `/c/{token}/calendar.ics`。固定路径 `/calendar.ics` 为 404 |
| 数据 | `interests`、`events`、`batches` 等表没有账户列。`settings` 只有 `id=1` 的一行 |
| Agent | 一个 Agent 令牌。`GET /api/v1/agent/context` 与 `POST /api/v1/batches` 的请求和响应形状不变。上传写入上面那一组不分区的表 |

## 3. 账户

两类账户，都存在数据库里，不另做注册表。

- **公开账户**正好一个，随数据库创建。没有登录令牌。匿名访客看的就是它的日程，订阅的也是它的日历。
- **受邀账户**由管理员在登录后创建。每个受邀账户有自己的登录令牌和另一份订阅密钥。

没有自助注册，没有密码。登录接口仍然只收一个 `token` 字符串。

### 3.1 令牌

- 管理员登录令牌仍只有一个，仍在 `credentials.json`。轮换方式不变。新初始化和 `rotate --role admin` 得到的是 16 个字符。已经写在文件里的旧管理员令牌继续有效，重启不更换。
- 邀请登录令牌和订阅密钥都用 `secrets.token_urlsafe(12)`。结果固定 16 个字符，取自 URL 安全的 Base64（大小写字母、数字、`-`、`_`），不是可枚举的短数字。96 位随机，短到能看完，也能整段复制进手机日历。
- 两者各抽一次，不是同一个值，也不由对方推导。比较哈希时用 `hmac.compare_digest`。
- 邀请登录令牌只在数据库保存 SHA-256，不保存原文。创建和重新签发的响应里给出原文，各一次。账户列表不包含令牌，点开账号也不能再查看已有令牌。不写入 `credentials.json`、`first-run-credentials.txt` 或日志。这些响应不给订阅地址，也不给订阅密钥。
- 管理员账号没有邀请令牌。管理账号里不提供查看管理员令牌。
- 新创建的受邀账户直接使用 16 位订阅密钥。
- 库里已经存在、长度不是 16 的个人订阅密钥，不能在保持原值的同时变短。数据库打开时把它换成新的 16 位密钥，只做这一次。旧的 `/c/{旧密钥}/calendar.ics` 变为 **404**。该账户的登录令牌不变，仍可登录；登录后在「订阅」页复制新地址，到手机日历里重新订阅。已经是 16 位的密钥，之后重启不再更换。
- 重新签发邀请令牌只更换登录哈希，新令牌也是 16 位。该用户的订阅密钥和 `/c/{订阅密钥}/calendar.ics` 不变。这个地址只在该用户自己登录后的「订阅」页出现。
- Agent 令牌仍用 `secrets.token_urlsafe(32)`，不在这次缩短里。
- 公开日历的地址是固定路径 `/public/calendar.ics`，路径里没有订阅密钥。`credentials.json` 里的 `calendar_token` 新生成时也是 16 位；已经存在的长值要等 `rotate --role calendar` 才更换。进程打开数据库时把它写回公开账户，但公开 feed 不读它。这次轮换不改变公开订阅地址，也不改变受邀账户的 `/c/{token}` 路径。
- 用公开账户那份 `calendar_token` 去请求 `/c/{token}/calendar.ics` 得到 404。个人路径只匹配 `kind='invite'` 且未撤销的账户。

### 3.2 删除

管理账号里的操作叫「删除」，不叫「禁用」，也不保留「已删除但仍展示」的状态。库里仍用 `revoked_at` 记下作废时间，不另做一套删除。管理员可以删除一个受邀账户，不能删除公开账户。

- 删除后，该账户不再出现在 `GET /api/v1/admin/accounts` 里。
- 已删除的登录令牌不能登录。已有的该账户会话在下一次请求失效。
- 该账户已发出的日历地址改为 **404**。不继续提供最后一份快照，也不做“停止更新但仍可订阅”的第二种状态。快照行可以留在库里，接口不读它。
- 这是较小的行为：feed 多一次作废判断，不必另做冻结发布。公开地址 `/public/calendar.ics` 不受影响。

### 3.3 会话与隐私

- 打开网站不是登录。匿名请求不写 `session` Cookie，也不自动进入任何账户。
- 管理员登录后只落在公开账户。兴趣、日程、候选和订阅地址都是这一份。没有切入受邀账户的接口。`POST /api/v1/admin/session/account` 不存在。
- 管理员不能读取受邀用户的兴趣、事件或日历内容。列表和按 id 读取都按公开账户过滤；用受邀账户的事件 id 请求得到 404。账户列表只含尚未删除的账户，字段是 id、种类、备注、撤销时间、创建时间。不含登录令牌、兴趣、事件或订阅地址。没有按账号查看令牌的接口。
- 受邀者用自己的邀请令牌登录后，只进入自己的账户。只能看和改自己的兴趣、自己的大模型页和自己的删除重置。不能切入别人，也不能看到别人的 Agent 令牌、兴趣或账号列表。
- 退出或会话失效之后，再打开网站仍是管理员那一份只读内容，不是刚才那个受邀账户。

日程、兴趣、订阅是同一套页面、同一套标题和文案。差别只在会话：管理员登录时配置和看到的是公开账户的日历和兴趣，订阅地址也是这一份；其他账户登录时配置和看到的是自己的日历和兴趣；未登录时只读展示管理员那一份，包括日程、兴趣和订阅，不能改。普通页面不写「公共日历」「公开日历的兴趣」这类把两套东西拆开的说法。

匿名可以读公开账户已发布到页面上的日程和兴趣名称，也可以在「订阅」页复制公开订阅地址。不能改兴趣，不能看个人订阅密钥，不能看 Agent 令牌，也不能打开大模型页或管理后台。公开账户的兴趣只有管理员会话能改。受邀者只能改自己账户的兴趣。

### 3.4 页面

不再有「设置」页。`GET /settings` 为 404。

导航对所有人显示三项：**日程** `/`、**兴趣** `/interests`、**订阅** `/subscribe`。已登录再显示两项：**大模型** `/model`、**管理后台** `/admin`。未登录不出现这两个入口。未登录时，任意页的页头右上角只有一个「登录」。点击后在当前页弹出小窗填写登录令牌，提交成功就留在当前页并进入该令牌对应的账户，不跳到单独的登录页。正文里的「登录」不加链接。已登录时同一位置只有「退出」，不同时再放「登录」。

| 页面 | 谁能打开 | 内容 |
| --- | --- | --- |
| `/` | 任何人 | 日程。标题和说明不随登录变化，不放订阅地址。未登录只读。已登录处理的是当前会话那一份 |
| `/interests` | 任何人 | 标题是「兴趣」，说明不随登录变化，不写「公共日历」。未登录为 200，只读展示管理员那一份，没有添加表单和移除按钮。已登录可以改当前会话的兴趣。`POST` 与 `DELETE` 仍要登录，无会话为 401 |
| `/subscribe` | 任何人 | 标题固定为「日历地址」，周围说明和步骤不随登录变化。未登录或管理员看到 `/public/calendar.ics`；其他账户只看到自己的 `/c/{token}/calendar.ics`。个人地址保留订阅密钥说明。不写监听、防火墙、HTTPS 或安全组，也不写「公开日历」。不放手动发布按钮；发布失败由服务自己重试。步骤只写 iOS 和 Android，不写鸿蒙，也不留「暂不支持」 |
| `/model` | 已登录 | 每个登录的账户都有这一页，用来连接自己的 Agent。标题、说明和步骤不随账户变化，不写「公共日历」。管理员登录时，服务器地址、Agent 令牌、最近接收和运行记录都是公开账户这一份。其他账户登录时，都是自己的那一份。接入说明里不写「连续三天无法连接才询问」那段。不提供按账户查看别人令牌的接口。无会话直接打开为 **403**，不转到登录页 |
| `/admin` | 已登录 | 每个登录的账户都能打开。里面的「删除和重置」不选择账户，只清当前登录的这一份：其他账户清自己的日历，管理员清公开账户。清空日历会保留兴趣；恢复初始状态会同时删除兴趣。「管理账号」只在管理员登录时出现：可以创建账户，也可以删除其他账户。删除后该账号从列表消失，令牌不能再登录，日历地址变为 404。不能删除管理员自己。列表有固定的最高高度，账号变多时在列表内部滚动。列表不放登录令牌，也没有「查看令牌」，不显示兴趣、订阅地址或别人的 Agent 令牌。普通账户看不到账号列表，调用账号列表接口为 **403**。无会话直接打开页面为 **403**，不转到登录页 |

创建账户和删除其他账户的接口仍只有管理员能调用。受邀者为 403，无会话的接口请求仍为 401。`GET /api/v1/agent/token` 在已登录时只返回当前这一份的 Agent 令牌。

## 4. 数据按账户分开

`interests`、`events`、`event_sources`、`candidates`、`batches`、`publications` 以及每个账户自己的 `settings`（`state_epoch`、`config_version`、`data_revision`、`active_publication_id`）都带账户。查询和写入都带账户条件，行不共用。

- 兴趣的“未删除则唯一”按账户加关键词，不按全库。
- 来源键、候选键在账户内唯一。`batch_id` 仍全库唯一，不回收；行上仍记它属于哪个账户。
- 快照仍只留该账户的当前指针和上一指针。一个账户的发布不删除另一个账户的快照。
- 删除和重置不选择账户，只清当前登录会话自己的那一份。管理员登录时这一份就是公开账户，其他账户清的是自己的。`calendar` 删该账户的事件、候选、批次和快照，保留兴趣，并写入一份空日历。`all` 再删该账户的兴趣。凭证和其他账户不动。请求里如果带了别的 `account_id`，拒绝，不清那个账户。已登录的账户可以调用重置。重置响应不返回兴趣或日程。

`POST /api/v1/batches` 的 JSON 不变，也不做另一套 Agent 运行器。公开账户的 Agent 令牌仍是 `credentials.json` 里的那一个，`rotate --role agent` 只换这一份。每个受邀账户在创建时另有一个 `secrets.token_urlsafe(32)` 的 Agent 令牌，数据库同时保存原文和 SHA-256，只供该账户在自己的大模型页读取。创建账户的响应里不返回它，账号列表里也没有它。Bearer 对上哪个令牌，上下文和上传就只读写哪一份：公开令牌仍只碰公开账户，受邀令牌只碰该受邀账户。已删除账户的令牌不能再上传。管理员会话不能靠受邀令牌读到对方的配置；受邀会话也不能靠公开令牌读到公开账户的 Agent 上下文。

## 5. 订阅地址

两条路径，不要混用。

- **公开**：`GET` 和 `HEAD /public/calendar.ics`。只读公开账户的当前快照。不需要登录，不使用路径密钥。`ETag` 与 `Cache-Control: no-cache` 与个人 feed 相同。`/calendar.ics` 仍是 404，不要把这个旧路径恢复成可读日历。
- **个人**：`GET` 和 `HEAD /c/{token}/calendar.ics`。`{token}` 是 16 位订阅密钥，不是登录令牌。只匹配未撤销的受邀账户。密钥错误、缺失、已撤销，或拿公开账户的 `calendar_token` 来请求，一律 404，不要 401。新账户从创建起就是这个长度。旧账户若仍是更长的密钥，打开数据库时换成新密钥，旧地址作废，需要重新订阅。公开地址没有这段密钥，缩短密钥不改变 `/public/calendar.ics`。

`subscription_url()` 是来源加上 `/public/calendar.ics`。来源的算法不变：非回环的 `BASE_URL` 原样使用；`--dev` 且 `BASE_URL` 是回环时，用 `detect_local_ip()`，探测不到则地址为空，页面保留「127.0.0.1 只能由这台电脑访问」那段说明。个人地址仍由 `subscription_url_for(token)` 拼成来源加上 `/c/{token}/calendar.ics`。

匿名和管理员的 `GET /api/v1/status` 返回公开地址。其他账户的 status 只返回自己的个人地址。订阅地址只出现在「订阅」页，不出现在日程页。该页标题是「日历地址」。

订阅步骤按系统分开写，因为核对后的路径不一样。页面只写这两条，先不支持鸿蒙，也不留占位说明：

- **iOS**（Apple 支持文档）：打开「日历」，进入日历列表，点「添加日历」→「添加订阅日历」，粘贴地址。iOS 26 接着点「查找」；iOS 18 及更早点「订阅」。
- **Android**（Google 日历帮助）：手机上的 Google 日历应用不能粘贴订阅地址。用电脑浏览器打开 Google 日历，在「其他日历」旁点「添加其他日历」→「通过网址添加」，粘贴地址后添加。手机在同步后看到它。

## 6. 明确不做

- 不改 Agent 接入说明的字段、上传路径和重试语义。公开账户的 Agent 令牌仍放在 `credentials.json`。
- 不做自助注册、密码、邮箱验证码。
- 不把撤销做成“日历仍可订阅但不再更新”。
- 不为每个账户做一套 Agent。
- 不让管理员切换到受邀账户，也不在管理接口里返回个人订阅地址或别人的 Agent 令牌。
- 不把账号列表给普通账户。
- 订阅页不写鸿蒙步骤，也不写「暂不支持」。
- 不把页头的「登录」做成跳转到单独登录页，也不在页面正文里给「登录」加链接。

## 7. 复查标准

- 无 Cookie 打开 `/`、`/interests`、`/subscribe` 都为 200，响应不设置 `session`。这三页标题和说明相同，不随登录改成另一套文案，页面上不出现「公共日历」或「公开日历的兴趣」。页头右上角是「登录」按钮，没有「退出」，也没有指向 `/login` 的链接；点开是当前页的登录小窗。正文里的「登录」不是链接。日程页没有订阅地址。`/interests` 的标题是「兴趣」，无会话时没有添加表单。`/subscribe` 的标题是「日历地址」，步骤只有 iOS 和 Android，没有鸿蒙说明。匿名 `GET /api/v1/events` 与 `GET /api/v1/interests` 只含公开账户的内容。匿名不能新增或删除兴趣。匿名 status 含公开订阅地址；`GET /public/calendar.ics` 返回公开快照。
- 已登录时页头同一位置是「退出」，不再同时放「登录」。
- 管理员可以新增公开账户的兴趣。受邀者登录后看不到这条兴趣；匿名再访问也看不到受邀者自己添加的兴趣。管理员也看不到受邀者的兴趣、事件或个人日历地址。账户列表不含登录令牌，也不含已删除账户。没有查看已有令牌的接口。数据库不保存登录令牌原文。删除后，该登录令牌不能建立会话，原个人日历地址为 404。
- 创建和重新签发的响应里只有登录令牌，没有订阅地址。受邀者登录后，status 里的个人地址与登录令牌不同。新创建账户的登录令牌和订阅密钥都是 16 位，且彼此不同。个人地址的路径段是订阅密钥，不是登录令牌。重新签发后个人地址不变，新登录令牌也是 16 位，旧登录令牌失效。
- 把库里的个人订阅密钥改成旧的长值并把 `user_version` 退回 4 之后再打开：密钥变成另一个 16 位值，旧地址 404，新地址仍能取到该账户的日历，登录哈希不变。再打开一次，密钥不再变。公开地址不变。新的管理员令牌是 16 位。Agent 令牌仍是 43 个字符。
- 删除后，该登录令牌不能建立会话，原个人日历地址为 404，账户列表里不再有它。公开地址仍可用。管理员账号不能删除。
- 未登录时页头没有「大模型」和「管理后台」。`/model` 与 `/admin` 对无会话是 403，不是 303。已登录的账户都能打开这两页。`/settings` 为 404。
- 受邀者的大模型页能读到自己的 Agent 令牌，读不到 `credentials.json` 里的公开 Agent 令牌。管理员的大模型页仍是公开这份令牌，账号列表和创建响应里都没有受邀者的 Agent 令牌。用受邀令牌上传或读取上下文，只碰到该账户；用公开令牌仍只碰到公开账户。受邀会话带着公开令牌读取上下文为 403。
- 受邀者的管理后台有「删除和重置」，没有「管理账号」，也没有创建账户。账号列表接口为 403。重置只清自己的账户。带了别的 `account_id` 为 403。管理员重置仍只清公开账户。
- 退出后首页回到公开日历。
- 重置不选择账户。管理员重置只清公开账户，其他账户的兴趣和日程还在。受邀者重置只清自己的。管理后台没有账户选择，也没有「查看令牌」。管理员的兴趣列表仍然看不到其他账户的兴趣。
