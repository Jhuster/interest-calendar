# 用量统计

管理员登录后，在导航栏或管理后台进入「用量统计」（`/usage`）。默认展示最近7个自然日，支持切换最近30天，含今天，均按北京时间计算。网站PV、UV和每日折线趋势位于页面顶部。接口为 `GET /api/v1/admin/usage`。普通受邀账户和 Agent 均无权查看。

## 指标口径

| 指标 | 统计方式 |
| --- | --- |
| 网站PV | 成功GET网站HTML页面的次数，包含匿名访问、登录用户和刷新。API、静态资源、健康检查、订阅、HEAD和失败响应均不计入 |
| 网站UV | 所选范围内按匿名浏览器标识去重，同一浏览器跨多天只计一次；趋势图中的UV按日去重，因此每日UV相加不等于范围UV |
| 累计账号 | 当前数据库里的全部账户，包含管理员和已撤销邀请；同时展示可用、撤销数量 |
| 活跃账号 | 所选范围（7或30天）内，登录后成功访问页面或执行接口操作的去重账户，含管理员。静态文件、健康检查、HEAD、Agent 请求、订阅轮询和未登录访客不计入 |
| Agent 回传账号 | 所选范围（7或30天）有已记录批次的去重账户，含成功和拒绝回执 |
| 成功 / 失败批次 | 当前 `batches` 中所选范围（7或30天）的唯一批次。状态码小于400为导入成功，否则为失败。按批次ID去重，重传不重复计数；鉴权失败、限流或缺少有效批次ID而未记录的请求不在此列。导入成功不等于发布已成功或手机已刷新 |
| 新增日程 | 当前事件记录中，创建时间位于所选范围（7或30天）的数量；更新已有日程不算新增 |
| 当前待核验 | 仍可用账户里的 pending 候选数量，与所选时间范围无关 |
| 核验操作 | 所选范围（7或30天）成功的确认、拒绝、合并、撤下、重新打开操作次数。同一个候选重新处理会再次计数 |
| 订阅请求 | 成功 GET 日历请求，含返回200和304。HEAD、错误密钥、撤销地址及失败响应不计入 |
| 公开 / 个人订阅 | 按订阅对应的账户种类拆分请求，未登录的公开订阅也计入公开请求 |
| 有订阅请求的个人账号 | 所选范围（7或30天）有成功订阅请求的个人账户去重数，排除公开账户。不是客户端数量，也不能识别同一账号的多部设备 |

订阅请求不等于订阅人数、手机查看次数或点击次数。日历客户端会自行轮询。页面同时展示最近回传时间和每天的活跃、批次、新增日程、订阅请求数。

## 数据保存与限制

- 网站PV/UV、活跃与订阅统计从功能上线开始记录，不回补。PV/UV在采集开始之前显示为空白或“—”，不伪造为0。页面展示开始记录时间；已存在的批次、日程和核验操作可以从业务库汇总。
- 核心用量仅按日期、内部账户ID、公开/个人种类保存活跃标记、订阅次数与304次数。
- 网站访问使用独立的随机 `calendar_visitor` Cookie（HttpOnly、SameSite=Lax、HTTPS下Secure，有效期90天）。服务器仅保存标识的SHA-256与日期去重，不保存原始标识，不绑定账户；页面和接口只返回汇总数字。
- 不记录用户名、IP、User-Agent、登录/订阅令牌、请求地址或日历内容。清除Cookie、禁用Cookie或更换浏览器可能被识别为新访客；匿名机器人访问页面也可能计入。UV不是自然人数，第一版不做跨设备识别或机器人识别。
- 汇总保存在 `bin/data/usage.sqlite3`，权限0600，按日保留90天，过期访客哈希与按日计数一起清理。重复登录、刷新页面不会增加同一天的活跃账户数。
- 统计库独立于业务库与登录会话，服务重启不清空；不进入日历数据库备份，清空/恢复日历不会倒退已收集的活跃和订阅计数。
- 账号、批次、日程和核验操作来自当前业务库；清空、恢复或迁移业务数据会影响这些指标。此页用于观察使用情况，不作为计费账单。
- 记录计数发生写入错误时保留正常服务响应并记录错误，管理员页面提示统计可能不完整。鉴权、导入和订阅不会因为一次统计写入失败而失败。

实现位于 `src/app/storage/usage.py`（按日计数）、`src/app/services/usage.py`（汇总）、`src/app/main.py`（请求记录与权限）、模板与静态资源。统计测试位于 `src/tests/test_usage.py`。
